§3
Field notes

      
Short notes from taking AI features out of the lab and into real teams.

      

        

          Note 01 · Early access
          
Tell testers what happened to their feedback

          
Early access programs usually fail quietly. Testers who never hear back stop testing honestly, and the next cohort is harder to fill.

          
So before anything I run reaches general availability, every tester gets a note: what we changed because of them, what we didn't, and why. It takes an afternoon. It turns a pilot into a relationship.

        

        

          Note 02 · Evals
          
Write the rubric for the most skeptical person in the room

          
Agents fail differently than chat. The final answer can look right while the steps behind it are wrong.

          
When I run an alpha for an agentic feature, I write the eval rubric with the customer's toughest reviewer in mind. Did it take the action they would have taken? Would they let it run unsupervised? What would they need to see to say yes? A rubric built that way can turn a nervous customer into a committed one.

        

        

          Note 03 · Operations
          
Build the front door before the program

          
Most early access programs start as a spreadsheet and a favor. When I built one from scratch, I started with intake: one front door tied to the product roadmap, so every request maps to something a team is actually shipping.

          
Then I let AI draft the outreach to product managers. People spend their time deciding which customers fit. The model writes the emails.
